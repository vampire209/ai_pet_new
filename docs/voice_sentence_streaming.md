# 对话中的逐句朗读

## 本次范围

用户确认先“生成完一句就读一句”，以后再升级低延迟实时语音对话，因此本次
在 11A 基础上优先实现普通本地发声和流式分句，而没有先做麦克风或角色克隆。
这是同一个 ChatWindow 内的功能，不是第二套聊天系统。

## 你现在怎么验收

1. 退出之前打开的旧版桌宠，用源码启动 `python main.py`，右键桌宠打开“AI聊天”。
   本次没有重新打包，旧的 EXE 不含这些新按钮。
2. 点击输入框下方的“试听”。未配置 DeepSeek Key、语音回复处于关闭状态时也能
   试听固定短句；它不会发送 API 请求，不增加聊天历史、待办或记忆。
3. 配好原有 DeepSeek API 后，点“语音回复：开”，正常发送消息。第一句结束后
   开始合成并播放，后面按序接续；文字仍然流式显示，无须复制文本。
4. 点击“停止朗读”：本轮后续语音不会恢复，但文字继续生成。发送下一条消息会
   取消旧音频。“停止”按钮仍然停止文字生成，并取消该轮语音。
5. 回复生成中打开开关，从下一轮起生效，不追读当前轮；关闭开关立即停音频。
   当前设置只在内存生效，重启默认关闭，不擅自启动语音。

使用现有 Windows 中文系统音色（本机实际识别到 Microsoft Huihui Desktop）。
它不是用户目标角色音色，也不是声音克隆模型。参考音频不会被偷偷忽略：
若尝试把参考路径传给此后端，会明确提示它不支持克隆。

## 实现与边界

```text
原有 DeepSeek 流式 chunk ───────────────→ 原有 UI / 完整回复历史
             │
             └→ SpeechSegmenter → VoiceService 句子队列
                 → 工作线程本地 TTS → 内存 PCM → 异步 Windows 播放器
```

- `voice/streaming_text.py`：跨 chunk 分句，代码围栏、链接目标、阅读建议隐藏
  JSON 不朗读；中文句末及时输出，英文句点保留必要上下文避免拆开小数。
  没有标点的长文本在约 180–240 字软分段，完成时只补尾句，不重复读全文。
- `voice/voice_service.py`：新增 `begin_reply/append_reply/end_reply`；原有
  `speak` 全句替换接口仍兼容。只播放一段，最多预合成后一段；待合成队列
  限制 64 句/12000 字，过量时明确停止本轮语音，文字继续显示。
- 每个语音回合有代次，每个音频另有独立编号。停止、清空、关闭、退出后，
  旧合成结果及旧播放完成事件不会复活音频或打断新音频。
- `voice/windows_tts.py`：工作线程延迟启动隐藏的 Windows PowerShell 辅助进程，
  复用一个 System.Speech 合成器，音频输出到内存。文本通过 JSON 数据传递，
  不拼进 PowerShell 代码；响应大小、超时均有限制。退出会终止并回收辅助进程。
- `voice/windows_audio_player.py`：用 Windows 原生异步 PCM 播放接口，Qt 定时器
  观察完成，不占用推理线程等待播放；停止时中断队列并安全释放原生缓冲区。
  音量只调整本段 PCM，不改系统或其他应用的音量。
- `voice/runtime.py`：正常桌面启动的组合入口。不开语音、不点试听，就不加载
  系统语音引擎或打开音频设备。没有引入额外 Python 依赖。
- `chat_window.py`、`ai/chat_theme.py`：同一个输入区加入小型开关、试听和停止
  朗读按钮，沿用现有浅蓝/奶白/淡紫风格。语音状态单独显示，不覆盖文字生成状态。
- `voice/tts_service.py`：补充模型/进程关闭的生命周期接口；推理仍在后台，
  关闭时不等待正在执行的合成锁，不改已有文字 ChatService 的行为。

正常的段与段之间可能有合成/设备启动间隔；这是逐句朗读，不是原生流式音频
或免按键全双工通话。英文缩写、混合语言及语调仍受系统音色能力限制。
真实音频是当前对话正文的朗读，TTS 不会自己生成第二份回答。

## 安全与现有功能

没有重写 ChatService、MemoryService、PersonaBuilder、ChatActionRouter 或
TodoManager，没有新增记忆库，没有改 DeepSeek 密钥或系统语音设置。
没有录音、音色素材、GPU 权重下载；没有新增 wav 缓存文件。
仍保留现有单词学习和阅读生词卡，附加 JSON 不会流入朗读。

当前没有使用 `QtMultimedia`：本机 Qt 安装不含该模块，本次采用 Windows
自带接口，没有为语音覆盖共享 Python/Qt 环境。`AIPetNew.spec` 未改，既有
Qt/ICU 排除逻辑保留，真正的 EXE 重新打包验收待后续安排。
